# Source access and evidence provenance

## Access statuses

- FULL_TEXT_OPENED — page or paper content was actually opened/read.
- OFFICIAL_DATA_OR_API_RETRIEVED — data were actually retrieved from an authoritative endpoint/API.
- SEARCH_SNIPPET_ONLY — only search-result text was available.
- METADATA_ONLY — title/abstract/record metadata only.
- INACCESSIBLE — blocked, failed, or unavailable.
- USER_SUPPLIED — provided directly by the user/chat/attachment.

## Rules

1. A search snippet is a discovery lead, not full-text verification.
2. A 401/403/404 result means the source was not read; do not cite its unseen content as verified.
3. State which exact claim a source supports.
4. Prefer primary sources for current market, issuer, regulatory, and instrument-specific facts.
5. Corroborate high-impact claims where possible.
6. For changing market data, record timestamp, timezone, instrument, venue, and whether the value is a close or an intraday snapshot.
7. Do not write "independently verified" unless a genuinely independent check was performed.
8. Do not use counts such as "checked 32 times" as a quality signal. Describe the actual reproducible checks.

## Evidence status

Keep verification status (VERIFIED, PARTIALLY VERIFIED, CONDITIONAL, REFUTED, RELATED BUT NOT EQUIVALENT, UNVERIFIED, INSUFFICIENT DATA) separate from source access status. Full access does not automatically mean a source is authoritative or relevant.
