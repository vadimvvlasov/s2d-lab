# Question-first workflow

## Purpose

A recap is useful when it answers the questions participants care about, not when it merely lists topics.

## Question classes

| Class | Meaning | How to present |
|---|---|---|
| Explicit question | Direct question in the chat | Attribute to speaker and quote/span |
| Implied question | Clear decision/problem implied by intention or disagreement | Label as inferred; explain why |
| Participant concern | Meaningful issue, not yet a precise question | Do not pretend it is fully specified |
| Researcher-added context | Context needed to answer or interpret the chat | Put in a separate context section |
| Rhetorical/joke | Banter without a substantive information need | Omit unless it reveals a real disagreement |

## Locate then answer

For each material question:
1. Identify the exact source spans and relevant context.
2. State what the participant needs to know or decide.
3. Break compound questions into separate research questions.
4. List participant-stated criteria and inferred criteria separately.
5. Retrieve only evidence relevant to that question.
6. Compare feasible options.
7. Recommend conditionally or state that evidence is insufficient.

QMSum is a relevant research foundation: it frames meeting summarization around answering queries and uses a locate-then-summarize approach. It does not prescribe S2D's investment logic; it supports the question-first retrieval pattern. See https://aclanthology.org/2021.naacl-main.472/.
